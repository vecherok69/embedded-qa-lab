# BUG-001: прошивка падає з необробленим OSError, якщо адреса I2C-датчика в коді не збігається з реальною (0x69 замість 0x68)

| Поле | Значення |
| --- | --- |
| Severity / Priority | Major / Medium |
| Виріб / плата, ревізія, серійний номер | Raspberry Pi Pico (RP2040), симуляція Wokwi, без серійного номера |
| Версія прошивки (або хеш) | `src/wokwi/03_i2c_wrong_addr.py`, MicroPython v1.28.0 (2026-04-06) |
| Відтворюваність | 1 з 1 прогонів (симулятор детермінований) |
| Дата | 2026-10-31 |

## Стенд

- Схема підключення: MPU6050 VCC → 3V3(OUT), GND → GND, SDA → GP16, SCL → GP17, AD0 не підключений (адреса датчика 0x68). Логічний аналізатор: D0 → GP16 (SDA), D1 → GP17 (SCL), GND. Схема описана в [тест-плані](../test-plan.md).
- Живлення: симулятор, 3,3 В від Pico.
- Прилади та налаштування: логічний аналізатор Wokwi, запис .vcd, PulseView з декодером I²C (SDA = D0, SCL = D1).
- Температура / середовище: не застосовується (симуляція).

## Кроки відтворення

1. Зібрати стенд за схемою вище, AD0 не підключати.
2. Завантажити `src/wokwi/03_i2c_wrong_addr.py` (у коді `ADDR = 0x69`).
3. Запустити симуляцію на 2–3 секунди, записати трейс на логічному аналізаторі.

## Очікуваний результат

Прошивка повідомляє, що датчика за адресою 0x69 немає (наприклад, `sensor not found at 0x69`), і далі або завершується з зрозумілою діагностикою, або пробує інші адреси зі списку `scan()`.

## Фактичний результат

- `scan` повертає `['0x68']`, тобто датчик на шині є.
- Читання WHO_AM_I за адресою 0x69 завершується `OSError: [Errno 110] ETIMEDOUT` на рядку 8, програма зупиняється, основний цикл читання не стартує.
- Повідомлення про помилку не вказує, що саме не так (яка адреса, що знайдено на шині).

## Додатково

- Обхідний шлях: виставити `ADDR = 0x68` або брати адресу з результату `i2c.scan()`.
- Що вже перевірено: датчик справний і відповідає на 0x68 (див. TC-01, TC-04 у [тест-плані](../test-plan.md)); живлення й лінії SDA/SCL правильні, поломка тільки в адресі в коді.
- Спостереження: у трейсі NACK виглядає так само, як при перевернутих SDA/SCL (TC-07), тому за одним лише NACK причину не визначити, треба дивитись адресу в кадрі.
