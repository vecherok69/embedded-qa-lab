# День 4: UART між Raspberry Pi 3 і Pico (крок 1, без дисплея)

Дата: 2026-11-02

## Мета

Перевірити обмін по UART між двома різними платами: Raspberry Pi 3 як тестовий хост, Raspberry Pi Pico як пристрій під тестом (DUT). На відміну від loopback дня 2, передавач і приймач тепер працюють від різних тактових генераторів.

## Стенд

| Що | Значення |
|---|---|
| Хост | Raspberry Pi 3 B+, `/dev/serial0 -> ttyS0` (mini-UART), Python 3.13.5, pytest 8.3.5 |
| DUT | Raspberry Pi Pico, MicroPython, прошивка `src/pico/uart_echo.py` (запуск з Thonny, на плату не зберігалась) |
| UART на Pico | `UART0`: GP0 TX (пін 1), GP1 RX (пін 2) |
| Живлення | Pi 3 від блока 5 В / 3 А, Pico від USB ПК; між платами лише спільний GND |
| Тести | `src/pi3/test_pico_uart.py` |

Комутація:

| Pi 3 | Pico |
|---|---|
| пін 8 (GPIO14 TXD) | пін 2 (GP1 RX) |
| пін 10 (GPIO15 RXD) | пін 1 (GP0 TX) |
| пін 6 (GND) | пін 3 (GND) |

Вибір пінів: за кодом старого проєкту дисплея (`src/pico/legacy/main.py`) дисплей ST7789 займає GP12 (RST), GP13 (DC), GP14 (CS), GP16 (MISO, не використовується), GP18 (SCK), GP19 (MOSI). GP0/GP1 вільні.

## Підготовка

- Старий проєкт з Pico (`main.py`, `st7789.py`) збережено в `src/pico/legacy/` до будь-яких змін на платі.
- Знахідка: Thonny не бачив Pico (`Unable to connect to COM4: port not found`). Причина: кабель micro-USB лише для заряджання, без ліній даних. Після заміни кабелю плата визначилась. Висновок для методики: перш ніж шукати дефект у пристрої, виключити кабель.

## Аналіз

### Чому soak повільніший, ніж у loopback (2,24 с проти 0,83 с)

- У loopback байт іде з TX одразу на RX, передавання і приймання накладаються, тож час близький до часу на дроті (9 байт × 10 біт / 115200 ≈ 0,78 мс на повідомлення, 0,78 с на 1000).
- З Pico схема «прийняв повністю, потім відправив»: DUT чекає `\n`, а вже потім повертає рядок. Час на дроті подвоюється: ≈ 1,56 мс на повідомлення, 1,56 с на 1000.
- Решта ≈ 0,68 мс на повідомлення (0,68 с на 1000) припадає на обробку в MicroPython на Pico (цикл `uart.any()`, пошук `\n`, склеювання `bytes`).

### Гіпотеза про похибку швидкості не підтвердилась

Очікування: у loopback похибка швидкості mini-UART не видна, бо TX і RX мають той самий такт; з Pico такти різні, тож на високих швидкостях можливі втрати.
Факт: втрат немає до 921600.
Розрахунок (за умови `core_freq` = 250 МГц на Pi 3 B+ з `enable_uart=1`, Pico на 125 МГц з дробовим дільником):

| baud | Pi 3 mini-UART, фактично | похибка | Pico, фактично | похибка |
|---|---|---|---|---|
| 115200 | 115314 | +0,10 % | 115207 | +0,006 % |
| 230400 | 229779 | −0,27 % | 230415 | +0,006 % |
| 460800 | 459559 | −0,27 % | 460829 | +0,006 % |
| 921600 | 919118 | −0,27 % | 920810 | −0,086 % |

Розбіжність між сторонами не більше ≈ 0,3 %, а UART витримує близько 2–3 %. Тому втрат і не мало бути. Ризик для mini-UART лишається, якщо частота ядра «плаває» (наприклад, без `enable_uart=1` або при зміні `core_freq`); це кандидат на окремий негативний тест.
