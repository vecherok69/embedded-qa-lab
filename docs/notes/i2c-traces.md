# Розбір I2C-трейсів (Wokwi + PulseView)

Стенд: Raspberry Pi Pico (MicroPython) + MPU6050 у симуляторі Wokwi.
Логічний аналізатор: D0 = SDA (GP16), D1 = SCL (GP17). Запис експортовано як .vcd і відкрито в PulseView з декодером I²C.

## 1. Сканування шини (`i2c.scan()`)

Скріншот: [i2c-scan-nack-0x08-0x0B.png](../screenshots/i2c-scan-nack-0x08-0x0B.png)

`scan()` по черзі звертається до адрес від 0x08 (0x00–0x07 зарезервовані). Кожна спроба на трейсі:
`S` (Start) → `Address write: XX` + `W` → `N` (NACK) → `P` (Stop).

На знімку це адреси 0x08, 0x09, 0x0A, 0x0B. Усюди NACK, бо на цих адресах пристроїв немає.
Адреса пристрою відповідає 7 бітам плюс біт запису, наприклад 0x08 → `0001000` + `0`.

## 2. Читання WHO_AM_I (регістр 0x75)

Скріншот: [i2c-whoami-read-0x68.png](../screenshots/i2c-whoami-read-0x68.png)

Послідовність на шині:

1. `S` → `Address write: 68` + `W` → `A` (ACK): датчик відгукнувся
2. `Data write: 75` → `A`: номер регістра WHO_AM_I
3. `Sr` (повторний Start, без Stop): перехід до читання
4. `Address read: 68` + `R` → `A`
5. `Data read: 68` → `N` (NACK від майстра на останньому байті) → `P` (Stop)

Результат: WHO_AM_I повернув 0x68, що збігається з очікуваним значенням для MPU6050. Датчик живий і це саме він.

## Що це дає для тест-плану

- Адреса пристрою ACK-ається (позитив), відсутні адреси NACK-аються (негатив).
- Читання регістра = запис адреси регістра + повторний Start + читання. На інтерв'ю це типове питання «як виглядає читання регістра по I2C».
- NACK від майстра на останньому прочитаному байті — це норма, а не помилка.
